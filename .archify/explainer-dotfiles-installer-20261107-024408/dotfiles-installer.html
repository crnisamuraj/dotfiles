How does the installer decide what to copy?

Long image

A

Answer

Only Source: and Target: after a successful run means no changes were reported for included paths. .installignore now controls which paths are included.

  1. The installer compares contents with checksums, not Git status or timestamps alone.1
  2. Missing or content-different files are copied. Matching file contents are skipped; metadata can still change.1
  3. There is no final success or no-change message. A successful repeat run can end after those two headings.21
  4. Ignored paths are excluded from both review and copying. The .archify report folder is ignored by the current rules.34

How does a normal install work?

Diagram structure
  • Select included paths resolve
  • Review differences review
  • Approval required? gate
  • Approve install? approve
  • Abort before writes abort
  • Run rsync sync
  • approve → abort · no
  • approve → sync · yes
  • gate → approve · yes
  • gate → sync · no
  • resolve → review · filtered
  • review → gate · inspected
  1. Select included paths ↗

    Validate paths, apply mandatory exclusions and .installignore, then list included entries with an rsync dry run against an empty temporary directory.

  2. Review differences ↗

    Review only included entries. Compare existing regular files with cmp, show diffs, and report entry replacements.

  3. Approve install? ↗

    Ask once for changes that remove or modify lines, binary changes, or symlink/type replacements. Rejection aborts everything before copying.

  4. Run rsync ↗

    Visit the included paths, compare file contents by checksum, merge directories, and print itemized changes.

--dry-run still reviews differences, but skips the prompt and previews rsync without writing. --approve-all skips confirmation, not review or change detection.51

How does .installignore work?

The control file is named .installignore, not .installerignore. It lives at the repository root and supplies rsync exclude patterns, one per line.36

Pattern or ruleScope and effectWhere it is enforced
.archifyExcludes matching files or directories at any depth, including this report folder.Current .installignore
.DS_StoreExcludes matching entries at any depth.Current .installignore
/README.md, /.gitignore, /install.shExcludes only those root entries. Nested files with those names remain eligible.Current .installignore
.gitExcludes matching entries at any depth.Mandatory in the installer; also listed in .installignore
/.installignoreExcludes the root control file itself.Mandatory in the installer

These are the current rules, not a fixed list of all possible exclusions.43

To add exclusions, put /private/ on a line to exclude the root directory, or *.tmp to exclude matching files at any depth.6

The installer builds one filter list and uses it for both the pre-install review and the final rsync. Ignored files produce no review diff or approval prompt.31

--only does not override exclusions. Selecting .archify or an ignored child fails with Excluded path before copying.3

Removing rules changes what can be installed

If .installignore is absent, only .git and root .installignore remain excluded. README.md, install.sh, and .archify are no longer excluded by default. Mandatory exclusions come before user rules, so include rules cannot override them. An ignore rule never deletes an earlier copy at the target.31

.gitignore controls Git, not installation. Hidden, untracked, and Git-ignored files can still be copied unless .installignore excludes them.6

What is copied, skipped, or protected?

SituationWhat the installer does
Entry is missing at the targetCopies it without a prompt.
Existing regular file contents matchSkips content transfer. Timestamps or executability may still update without a prompt.
Text changes only add linesShows the diff and installs without a prompt.
Text changes remove or modify lines; binary contents differShows the change and requires approval unless --approve-all is set.
Existing symlink target or entry type differsRequires approval unless --approve-all is set. Source symlinks stay symlinks.
Entry exists only at the targetRetainedKeeps it. There is no deletion mirror.
A non-empty target directory conflicts with a source file or symlinkNot replacedErrors instead of forcibly removing the directory.

These rules come from the preflight review and rsync configuration.2716

These actions apply only to paths that pass the ignore filters. Excluded source changes and destination-only entries are left alone.31

--only PATH narrows the selection but keeps its relative destination path. Existing directory permissions and timestamps are retained. File timestamps and executability follow the source.86

Approval is not a backup or a transaction

Matching files are overwritten without backups. A rejected approval prevents all copying, but a later rsync failure can leave partial changes. No packages are installed, application hooks run, or services restarted. See the source safety notes.6
